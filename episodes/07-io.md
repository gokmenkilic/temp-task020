:::::::::::::::::::::::::::::::::::::: questions 

- How much of a code's runtime is spent reading and writing data?
- Why should we use a representative I/O workload when benchmarking?

::::::::::::::::::::::::::::::::::::::::::::::::

::::::::::::::::::::::::::::::::::::: objectives

- Identifying the time spent reading and writing data.
- Calculating an I/O performance ratio using the application's total runtime.

::::::::::::::::::::::::::::::::::::::::::::::::

If you are using HPC for your code, probably worth to cheking I/O benchmarking. Because these type of codes usally read and write from disk and save several snaphots. In regards the data workflows it may appear fine, however in some case can significally affect on the total execution time. Code may utulize resoruces well while spending a lot time of its runtime I/O operations. Therefore, we will learn how to assess I/O performance in this section.

We will use the same method as before with some examples to desctibe I/O benchmkaring and the necesseary metrics to interpret.

::::::::::::::::::::::::::::::::::::: callout

To evaluate I/O performance, a code is considered good performance if it spends less than 20% of its runtime on I/O.

## Preparation

You can use a typical run of code which familar to you or your own code that in format used in test your developments runs. To be realistic for I/O benchmark preperation do not temp to cut I/O to improve the performance. If you want to prepare a case that isolated from heavy I/O routines, it could be useful for other rubrics, where you want to isolate compute performance or level of benchmkark you want to exclude. On I/O, there are not much tools to be used and it is relativelty focused on Darshan. Darshan a I/O tool, which records the I/O calls a code while it runs. In this way it can measure MPI-IO,HDF5, PNetCDF and POSIC calls on disk with minumum overhead. 

::::::::::::::::::::::::::::::::::: callout

To be able to pick measurments from I/O calls, you make to use that you compile the code via appropriate compiler wrappers on the system you are using. Please check relavant modeuls and paths on your own documentation.
