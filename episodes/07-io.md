::::::::::::::::::::::::::::::::::::: objectives

If you are using HPC for your code, probably worth to cheking I/O benchmarking. Because these type of codes usally read and write from disk and save several snaphots. In regards the data workflows it may appear fine, however in some case can significally affect on the total execution time. Code may utulize resoruces well while spending a lot time of its runtime I/O operations. Therefore, we will learn how to assess I/O performance in this section.

To evaluate I/O performance, a code is considered good performance if it spends less than 20% of its runtime on I/O.

## Preparation

You can use a typical run of code which familar to you or your own code that in format used in test your developments runs. To be realistic for I/O benchmark preperation do not temp to cut I/O to improve the performance. If you want to prepare a case that isolated from heavy I/O routines, it could be useful for other rubrics, where you want to isolate compute performance or level of benchmkark you want to exclude.
