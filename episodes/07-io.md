:::::::::::::::::::::::::::::::::::::: questions 

- How much of a code's runtime is spent reading and writing data?
- Why should we use a representative I/O workload when benchmarking?

::::::::::::::::::::::::::::::::::::::::::::::::

::::::::::::::::::::::::::::::::::::: objectives

- Identifying the time spent reading and writing data.
- Calculating an I/O performance ratio using the application's total runtime.

::::::::::::::::::::::::::::::::::::::::::::::::

If you are using HPC for your code, probably worth to cheking I/O benchmarking. Because these type of codes usally read and write from disk and save several snaphots. In regards the data workflows it may appear fine, however in some case can significally affect on the total execution time. Code may utulize resoruces well while spending a lot time of its runtime I/O operations. Therefore, we will learn how to assess I/O performance in this section.
